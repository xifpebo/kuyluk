# Security policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately to the maintainers (for example by email to
the site operator). Do not open public issues for security problems. Include steps to
reproduce, the affected URL or endpoint, and the impact you observed. We aim to confirm
receipt within 3 working days.

## Supported versions

Only the latest `2.x` release receives security fixes.

## Operational guidance

- **Secrets:** `APP_SECRET` signs CSRF tokens. Rotating it invalidates every CSRF token,
  so users simply reload the page. Never commit `.env`.
- **Accounts:** keep the number of super-admins small. Give day-to-day staff the Manager role.
  Deactivate accounts instead of sharing them; deactivation and role changes end all sessions
  of that user immediately.
- **Lockouts:** a locked account unlocks automatically, or a super-admin can unlock it under
  *Users → ⋮ → Unlock*. Repeated `auth.locked` or `access.denied` entries in the activity log
  should be investigated.
- **Temporary passwords:** passwords generated by *Create user* or *Reset password* are shown
  once. Send them over a separate secure channel; the user must change them at first login.
- **Audit log:** entries are append-only at the application level. For regulatory needs, also
  restrict `update` and `remove` on the `auditlogs` collection at the MongoDB role level and ship
  the application logs to external storage.
- **Uploads:** only JPEG, PNG and WebP images whose magic bytes match are accepted. They are
  stored under random names and served with `nosniff` and a sandbox CSP. Keep the uploads
  directory outside any path where the web server executes scripts.
- **Network:** run behind HTTPS, set `TRUST_PROXY` correctly (otherwise rate limits key on the
  proxy IP), and consider an IP allow-list or VPN for `/admin` and `/api/admin`.
- **Dependencies:** run `npm audit` regularly. The app has three runtime dependencies (express,
  mongoose, dotenv); security features use Node.js built-ins (`crypto.scrypt`, HMAC, `timingSafeEqual`).

## Security controls at a glance

| Area | Control | Code |
| --- | --- | --- |
| Sessions | Server-side, hashed tokens, idle and absolute expiry, `tokenVersion` revocation | `src/security/session.js` |
| CSRF | Session-bound HMAC token plus Origin / Sec-Fetch-Site checks | `src/security/csrf.js` |
| Rate limiting | Fixed window, MongoDB or memory store, IPv6 /64 grouping | `src/security/rateLimit.js` |
| Passwords | scrypt, policy, history, lockout, dummy-hash timing | `src/security/password.js`, `src/services/authService.js` |
| RBAC | Permission matrix, per-route guards, denials audited | `src/security/rbac.js`, `src/middleware/auth.js` |
| Input | Strict schemas, text sanitising, `sanitizeFilter` | `src/lib/schema.js`, `src/lib/text.js`, `src/db.js` |
| Output | CSP with Trusted Types, escaping templates | `src/security/headers.js`, `src/views/engine.js`, `public/js/lib/dom.js` |
| Audit | Append-only log with diffs and retention | `src/services/audit.js`, `src/models/AuditLog.js` |
